# Визуализатор графа зависимостей npm
## 1. Общее описание
Данный проект представляет собой CLI-утилиту (интерфейс командной строки) для анализа и визуализации графа 
зависимостей npm-пакетов. Инструмент позволяет получать данные о прямых и транзитивных зависимостях заданного пакета, 
строить граф зависимостей с учетом заданной глубины, а также визуализировать его в виде текстового ASCII-дерева или
диаграммы на языке PlantUML. Инструмент написан на языке Python (версия 3.8+). Сторонние библиотеки для получения 
зависимостей не используются — данные получаются напрямую через HTTP-запросы (модуль urllib) к официальному реестру npm.

## 2. Описание функций и настроек
Утилита поддерживает следующие параметры командной строки:
-p, --package (обязательный) — Имя анализируемого пакета (например, express).
-r, --repo (обязательный) — URL-адрес репозитория npm (например, https://registry.npmjs.org) или путь к файлу тестового репозитория.
-m, --mode — Режим работы. real (по умолчанию) — скачивание данных из интернета, test — чтение графа из локального файла.
-v, --version — Версия пакета. По умолчанию latest (последняя доступная).
-a, --ascii — Флаг для вывода графа зависимостей в виде ASCII-дерева.
-d, --depth — Максимальная глубина анализа зависимостей (целое число >= 1). По умолчанию 3.
-f, --filter — Подстрока для фильтрации. Пакеты, в имени которых есть эта подстрока, не учитываются при анализе.
-o, --order — Флаг для вывода порядка загрузки зависимостей (топологическая сортировка).

## 3. Команды для сборки и запуска
Проект не требует сборки или установки сторонних зависимостей (используется только стандартная библиотека Python).
Для запуска скрипта сделайте его исполняемым (в Linux/macOS):
```
bash
chmod +x run.sh
```
Запуск утилиты осуществляется через скрипт run.sh:
```
bash
./run.sh [параметры]
```
## 4. Примеры использования
Пример 1. Анализ реального пакета (сбор данных и порядок загрузки):
```
bash
./run.sh --package express --repo https://registry.npmjs.org --depth 1 --order
```
Вывод (фрагмент):
```
--- Порядок загрузки зависимостей ---
1. qs
2. depd
...
28. express
```
Сравнение с реальным менеджером пакетов: при выполнении npm install express реальный менеджер пакетов скачивает 
зависимости в порядке, определяемом его внутренним алгоритмом (часто параллельно). Наша реализация выдает 
последовательный корректный порядок (топологическую сортировку) от самых глубоких зависимостей к корневому пакету. 
Расхождения могут быть обусловлены тем, что реальный npm объединяет и оптимизирует деревья зависимостей для 
избежания дублирования.
Пример 2. Анализ тестового графа (вывод в формате ASCII-дерева):
```
bash
./run.sh --package A --repo tests/test_data/sample_graph.txt --mode test --depth 2 --ascii
```
Вывод:
```
--- ASCII-дерево зависимостей ---
A
|-- B
│   `-- D
`-- C
    `-- E
```
Пример 3. Генерация диаграммы PlantUML:
```
bash
./run.sh --package A --repo tests/test_data/sample_graph.txt --mode test --depth 2
```
Вывод (фрагмент):
```
--- Визуализация в формате PlantUML ---
@startuml
skinparam defaultFontName Monospaced
"A" --> "B"
"A" --> "C"
"B" --> "D"
"C" --> "E"
@enduml
```
Сравнение с инструментами визуализации: штатные средства npm (например, сервис npmgraph.js.org) строят интерактивные
графы, объединяя общие зависимости в один узел. Наша утилита генерирует статичное текстовое описание PlantUML, 
которое может быть отрисовано в любом редакторе. Расхождения заключаются в том, что наш инструмент фокусируется на 
строгой иерархии вызовов (дереве), а не на оптимизированном облаке зависимостей.
